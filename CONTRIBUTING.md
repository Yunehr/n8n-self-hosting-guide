# Contributing to Self-Hosted n8n + Local AI Infrastructure Guide 
Thank you for your interest in contributing! 
We welcome community reviews, hardware testing benchmarks, Docker Compose optimizations, and documentation refinements.

## 📜 Code of Conduct 
This project follows our [Code of Conduct](CODE_OF_CONDUCT.md). 
By participating, you are expected to uphold a welcoming and respectful environment for all contributors. 

## 💡 Ways to Contribute 
- **Hardware Benchmarks**: Share performance findings across different hardware (e.g., Raspberry Pi 5, mini PCs, custom GPUs).
- **Docker & Script Optimizations**: Improve \`docker-compose.yml\`, environment templates, or automated deployment scripts. 
- **Documentation & Workflows**: Clarify setup steps, fix typos, or contribute new n8n AI workflow examples.
- **Review Open PRs**: Help review open Pull Requests submitted by the community.

## 🐛 Reporting Bugs & Issues 
1. Search [Existing Issues]([suspicious link removed]) to verify the bug hasn't already been logged.
2. If it is new, open an Issue using the Bug Report template.
3. Include your operating system (Windows WSL2, Linux, macOS), hardware specs, Docker version, and relevant error logs.

## 🔒 Reporting Security Vulnerabilities 
Please do **NOT** open public issues for security vulnerabilities or credential leaks. Refer to [SECURITY.md](SECURITY.md) to report issues privately. 

## 🚀 Pull Request Workflow 
1. **Fork the Repository** and create a focused branch from `main`:
```bash
   git checkout -b feature/short-description
```
2. **Test Your Changes**: Validate the proposed documentation changes or updates.
3. **Commit Changes**: Use concise, descriptive commit messages.
4. **Submit Your PR**:
    - Link related issues (e.g., Closes #12)
    - Summarize what changed and why.
